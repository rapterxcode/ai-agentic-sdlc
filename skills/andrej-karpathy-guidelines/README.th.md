# สรุปภาษาไทย — 4 กฎเหล็กจาก andrej-karpathy-skills

คำอธิบายฉบับเข้าใจง่ายของ [`SKILL.md`](SKILL.md) ในโฟลเดอร์นี้ — ต้นฉบับภาษา
อังกฤษคือของจริงที่ AI อ่าน ไฟล์นี้มีไว้ให้คนอ่านทำความเข้าใจก่อนว่าแต่ละกฎ
แก้ปัญหาอะไร และควรใช้ตอนไหน

## กฎเหล็กที่ 1 — Think Before Coding (คิดก่อนเขียน)

AI ส่วนใหญ่มักจะ "เดา" ความต้องการของเราแล้วเขียนโค้ดออกมาเลย กฎข้อนี้จะ
เบรกพฤติกรรมนั้น

- **คืออะไร:** บังคับให้ AI ต้องบอก "ข้อสันนิษฐาน" ของตัวเองออกมาก่อน ถ้ามี
  อะไรไม่ชัดเจน ต้องเสนอทางเลือกให้เราตัดสินใจ ห้ามเลือกเองเงียบๆ
- **ใช้ตอนไหน:** เมื่อสั่งงานที่ตีความได้หลายแบบ เช่น "ทำให้ Search เร็วขึ้น"
  (เร็วขึ้นแบบ response time หรือรองรับคนได้มากขึ้น?)
- **เทคนิคคือ:** AI จะพิมพ์แผนงานและทางเลือกมาให้คุณเลือกก่อนเสมอ ถ้าคุณเห็น
  ว่ามันเข้าใจผิด ก็เบรกมันได้ทันทีก่อนที่มันจะรื้อโค้ดพัง

## กฎเหล็กที่ 2 — Simplicity First (เรียบง่ายที่สุด)

AI ชอบโชว์พาวเวอร์ สั่งให้ทำระบบลดราคา มันดันไปสร้าง Class, Interface, และ
Design Pattern มาเต็มไปหมด ทั้งที่ต้องการแค่ Function เดียว

- **คืออะไร:** กฎที่สั่งให้ AI เขียนโค้ดให้น้อยที่สุดเท่าที่จะแก้ปัญหาได้
  ห้ามเขียนเผื่ออนาคต ห้ามสร้าง Abstraction ที่ไม่ได้ขอ
- **ใช้ตอนไหน:** ทุกครั้งที่สั่งเขียน Feature ใหม่
- **เทคนิคคือ:** กฎนี้จะเช็คว่า "ถ้า Senior Dev มาเห็นโค้ดนี้ จะด่าว่า
  Overengineer ไหม?" ถ้าใช่ AI จะต้องลดความซับซ้อนลงทันที

## กฎเหล็กที่ 3 — Surgical Changes (แก้เฉพาะจุด)

เคยไหม? สั่งแก้ Bug นิดเดียว แต่ AI ดันไปแก้ Format, เปลี่ยนชื่อตัวแปร, หรือ
แก้ Comment ในไฟล์นั้นซะเละเทะ

- **คืออะไร:** บังคับให้ AI ทำตัวเหมือนศัลยแพทย์ — แตะเฉพาะบรรทัดที่จำเป็น
  ต้องแก้เท่านั้น ห้ามแตะโค้ดส่วนอื่น ห้ามเปลี่ยน Style โค้ดเดิมแม้ว่า AI
  จะไม่ชอบก็ตาม
- **ใช้ตอนไหน:** เวลาแก้ Bug หรือเพิ่ม Feature เล็กๆ ในไฟล์ที่มีโค้ดอยู่แล้ว
  เยอะๆ
- **เทคนิคคือ:** ทุกบรรทัดที่ AI แก้ไข จะต้องสามารถอธิบายได้ว่า "เกี่ยวข้อง
  กันยังไงกับคำสั่งของคุณ" ถ้าไม่เกี่ยว ห้ามแก้เด็ดขาด

## กฎเหล็กที่ 4 — Goal-Driven Execution (ทำงานตามเป้าหมาย)

เวลาสั่ง AI ว่า "แก้ Bug ให้หน่อย" มันมักจะแก้แบบมั่วๆ แล้วบอกว่าเสร็จแล้ว
ทั้งที่ยังพังอยู่

- **คืออะไร:** เปลี่ยนคำสั่งลอยๆ ให้เป็น "เป้าหมายที่ตรวจสอบได้"
  (Verifiable Goals) เช่น แทนที่จะสั่ง "แก้ Bug" AI จะเปลี่ยนเป็น "เขียน
  Test ให้เจอ Bug -> ทำให้ Test ผ่าน"
- **ใช้ตอนไหน:** งานที่มีหลายขั้นตอน หรืองานที่ต้องใช้เวลาทำนานๆ
- **เทคนิคคือ:** AI จะทำงานเป็น Loop คือ ทำ -> ตรวจสอบ -> ทำต่อ จนกว่าจะ
  บรรลุเป้าหมายจริงๆ ไม่ใช่แค่ทำเสร็จแล้วจบกัน

## สรุป: ไฟล์เดียว เปลี่ยน AI ได้จริงหรือ?

ความเจ๋งของ andrej-karpathy-skills คือความเรียบง่าย — วางไฟล์เดียว
AI ก็อ่านและทำตามกฎ 4 ข้อนี้ทันที มีสองวิธีวางไฟล์ (ต้นฉบับให้เลือกได้ทั้ง
สองแบบ):

1. **เป็น skill** (วิธีที่ repo นี้ติดตั้งให้โดย `install/install-*.sh`):
   `SKILL.md` ในโฟลเดอร์นี้ ถูกวางที่ `~/.claude/skills/andrej-karpathy-guidelines/`
   (หรือ `~/.codex/skills/`, `~/.gemini/skills/`, `~/.kiro/skills/`) — ใช้
   ได้ทุกโปรเจกต์ทันทีที่ AI ตัดสินใจว่าเกี่ยวข้อง
2. **เป็น CLAUDE.md ต่อโปรเจกต์** (วิธีที่ต้นฉบับเรียกว่า "Option B",
   เป็นไฟล์ตายตัวที่ AI โหลดทุกครั้งไม่ต้องรอตัดสินใจ): copy
   [`CLAUDE.md`](CLAUDE.md) ในโฟลเดอร์นี้ไปต่อท้าย `CLAUDE.md`
   ของโปรเจกต์คุณโดยตรง
