AIDLC-lite Workflow & Architecture

Explore how aidlc-lead orchestrates specialist sub-agents and enforces rigorous human approval gates.

Phase 0

Classify, Route & Select Scope

Route tasks into new, feature, bugfix, refactor, or investigation scopes. Heavy routing decides whether to decompose complex multi-domain structures.

Phase 1

Establish Repository Truth

Deep dive into codebase, existing APIs, tests, and configuration. The researcher agent explores codebase references thoroughly to back decisions with solid evidence.

Phase 2 & 3

Requirements & Technical Design

Formalize constraints and architectural specifications. Human interaction triggers Gate A for technical design sign-off.

Phase 4

Implementation Plan & Review

Write sequential task items. The specialized plan-reviewer acts as Gate 1, enforcing corrections. Human reviews the plan at Gate B.

Phase 5

Execution & TDD Implementation

Surgical, single-file edits verifying with Test-Driven Development. Tasks crossing authentication/secrets activate security-auditor at Gate 2.

Phase 6 & 7

Review, Build & Integrated Verification

Verify tests, syntax, and static types. devsecops-engineer scans for CVEs/leaked keys at Gate 3, while test-quality-auditor blocks fake tests at Gate 4.

Phase 8

Release Readiness Analysis

Prepare migrations, version updates, and rollbacks. Destructive or prod actions are checked and approved by Human in Gate C.

Phase 9

Operations & Knowledge Handoff

Write clean runbooks and update markdown index. Ensure comprehensive transparency and handover.

Verified 2.13.0 Kiro CLI Integration

Kiro CLI fully supports the modern multi-agent standard with classic JSON rosters. Our automated installer places agents into your user directory and configures `aidlc-lead` as your default pilot.

  • Rosters stored inside ~/.kiro/agents/
  • Steering logic loaded from ~/.kiro/steering/ai-team-global-rule.md
  • Karpathy guidelines (Always-On) merged into ~/.kiro/steering/ai-team-karpathy-guidelines.md
  • Skills mapped flat into ~/.kiro/skills/
kiro-install.sh

# Run the central installer wrapper

./install/install-kiro.sh --set-default-agent

# Alternatively, run manually by copying artifacts:

mkdir -p ~/.kiro/agents && cp agents/kiro-agents/*.json ~/.kiro/agents/

# Set default agent inside ~/.kiro/settings/cli.json

kiro-cli agent set-default aidlc-lead

Verified 2.1.216 Claude Code Setup

Claude Code handles sub-agents using Markdown specifications. Use project-scope installation to lock your project settings or establish a system-wide roster.

  • System agents stored at ~/.claude/agents/
  • Project-local agents at <project>/.claude/agents/
  • Enforced steering rule attached directly to CLAUDE.md
  • Karpathy guidelines (Always-On) merged into the same CLAUDE.md
claude-install.sh

# Install system-wide and configure project target

./install/install-claude.sh --project ~/code/my-app --set-default-agent

# Set project default agent via config:

echo '{"agent": "team-leader"}' > ~/code/my-app/.claude/settings.json

Verified 0.144.6 Codex CLI Integration

Codex uses TOML configurations to describe specialist agents. Multi-agent processing is managed from the root context using custom directives declared in `AGENTS.md`.

  • TOML agents stored inside ~/.codex/agents/
  • User-level skills stored flat inside ~/.agents/skills/
  • Orchestration routing merged into ~/.codex/AGENTS.md
  • Karpathy guidelines (Always-On) merged into the same AGENTS.md
codex-install.sh

# Run the Codex specific installer

./install/install-codex.sh --install-agents

# Generates TOML from Markdown source-of-truth using:

python3 install/generate-agents.py --platform codex

Verified 0.51.0 Gemini CLI / Antigravity

Gemini handles agents through clean Markdown files. Triggering specialists is done by explicitly addressing them using `@<agent-name>` in prompts.

  • Markdown agents stored in ~/.gemini/agents/
  • Skills stored flat at ~/.gemini/skills/
  • Root steering rules appended to ~/.gemini/GEMINI.md
  • Karpathy guidelines (Always-On) merged into the same GEMINI.md
gemini-install.sh

# Run the Gemini installer

./install/install-gemini.sh --install-agents

# Headless setup requires setting context authorization:

export GEMINI_CLI_TRUST_WORKSPACE=true
