# 🧠 สารบัญอธิบายความสามารถย่อยและการทำงานของแต่ละ Skill (Complete Skills & Execution Dictionary)

คู่มือนี้รวบรวมคำอธิบายการทำงาน วัตถุประสงค์ และ **กลไกการเรียกใช้งาน (Execution Mechanism) ของความสามารถย่อยทั้งหมด** เพื่อช่วยให้ทั้งผู้พัฒนาที่เป็นมนุษย์ และตัวแทนเอเจนท์ AI เข้าใจโครงสร้างการดึงประสิทธิภาพของแต่ละทักษะไปใช้งานจริงได้อย่างถูกต้อง

---

## 🛠️ รูปแบบกลไกการทำงานของแต่ละ Skill (Execution Mechanisms)

ความสามารถย่อย (Skills) ทั้งหมดในระบบถูกจัดสรรกลไกการรันออกเป็น 3 รูปแบบหลัก เพื่อประสิทธิภาพการใช้ Token และป้องกันความเสี่ยง:

1. **`Slash Command (เรียกใช้งานตรงๆ)`**: เป็นคำสั่งเรียกใช้โดยมนุษย์หรือเอเจนท์หลักผ่าน CLI (เช่น `/skill [ชื่อสกิล]` หรือ `$skill [ชื่อสกิล]`) เพื่อเริ่มต้นตรรกะหรืองานเฉพาะด้านแบบทันที
2. **`Always-On Guardrail (รันเบื้องหลังตลอดเวลา)`**: ทักษะที่ถูกฝังไว้ใน Steering Files (`CLAUDE.md`, `GEMINI.md`, `AGENTS.md`) คอยสอดส่อง พิทักษ์ความปลอดภัย และสกัดกั้นพฤติกรรมที่ไม่พึงประสงค์ของ AI ตลอดเวลาโดยผู้ใช้ไม่ต้องสั่งเอง
3. **`Workflow-Activated (ทำงานเมื่อเข้าเฟสที่กำหนด)`**: ถูกอัญเชิญขึ้นมารันโดยอัตโนมัติเมื่อเอเจนท์ผู้ประสานงานหลักเข้าสู่ขั้นตอน SDLC ที่สอดคล้องตามเกณฑ์ประเมิน (เช่น เข้าสู่เฟสดีบั๊ก จะอัญเชิญ `systematic-debugging`)

## 🌟 1. 9arm Skills (ทักษะความรัดกุมในการดีบั๊ก)

กลุ่มทักษะสไตล์พี่เก้า มุ่งเน้นการสร้างวินัยดีบั๊กเพื่อประสิทธิภาพและความรัดกุมสูงสุด:

### 1. `debug-mantra` (มนตราดีบั๊ก)
- **กลไกการทำงาน:** `Always-On Guardrail (รันเบื้องหลังตลอดเวลา)`
- **ตรรกะการรัน:** เมื่อเกิดข้อผิดพลาดในการรันคอมไพล์หรือทดสอบพัง ระบบจะบังคับให้ AI ท่องขั้นตอนควบคุมสติเพื่อรวบรวมหลักฐานและข้อมูลความจริงเชิงประจักษ์ (Empirical Data) แทนการเดาสุ่มแก้ไขโค้ด
- **คำสั่งเรียกใช้:** รันอัตโนมัติเบื้องหลังเมื่อเทสพัง หรือเรียกแมนนวลด้วย `/skill debug-mantra`

### 2. `post-mortem` (การชันสูตรปัญหา)
- **กลไกการทำงาน:** `Slash Command (เรียกใช้งานตรงๆ)`
- **ตรรกะการรัน:** เมื่อระงับปัญหาระบบล่มหรือบั๊กครั้งใหญ่สำเร็จ มนุษย์จะเรียกคำสั่งนี้เพื่อให้ AI วิเคราะห์และจัดทำรายงานหาสาเหตุหลัก (Root Cause) และเสนอแผนสกัดกั้นถาวร
- **คำสั่งเรียกใช้:** `/skill post-mortem` หรือ `$skill post-mortem`

### 3. `qwen-agent` (ระบบสแกนเนอร์ Qwen)
- **กลไกการทำงาน:** `Workflow-Activated (ทำงานเมื่อเข้าเฟสที่กำหนด)`
- **ตรรกะการรัน:** ถูกอัญเชิญในขั้นตอนตรวจสอบผลลัพธ์บิวด์ เพื่อสถาปนาโมเดลภาษาขนาดใหญ่ตระกูล Qwen เข้ามาทำหน้าที่เป็นผู้ตรวจสอบความเป็นระเบียบเรียบร้อยของโค้ด
- **คำสั่งเรียกใช้:** เรียกใช้งานอัตโนมัติในกระบวนการ QA หรือเรียกตรงๆ ด้วย `/skill qwen-agent`

### 4. `scrutinize` (การพินิจพิเคราะห์)
- **กลไกการทำงาน:** `Always-On / Slash Command`
- **ตรรกะการรัน:** ตรวจทานโค้ดทีละบรรทัด ค้นหาจุดขัดแย้งเชิงตรรกะและ Edge Cases ทั้งหมดอย่างละเอียดยิบก่อนกดยืนยันการเปลี่ยนแปลงโค้ด
- **คำสั่งเรียกใช้:** `/skill scrutinize [ไฟล์เป้าหมาย]`

### 5. `management-talk` (การสื่อสารเชิงบริหาร)
- **กลไกการทำงาน:** `Slash Command (เรียกใช้งานตรงๆ)`
- **ตรรกะการรัน:** แปลงและย่นย่อรายละเอียดงานพัฒนาเชิงเทคนิคที่ซับซ้อนให้กลายเป็นรายงานสถานะ (Status Report) สั้นๆ สรุปความก้าวหน้าสำหรับผู้จัดการหรือลูกค้า
- **คำสั่งเรียกใช้:** `/skill management-talk`

### 6. `qwenchance` (การจำลองโอกาส)
- **กลไกการทำงาน:** `Slash Command (เรียกใช้งานตรงๆ)`
- **ตรรกะการรัน:** สรุปสมมติฐานและจำลองผลกระทบเมื่อต้องออกแบบโครงสร้างระบบภายใต้ทรัพยากรจำกัด
- **คำสั่งเรียกใช้:** `/skill qwenchance`

## 🛡️ 2. Andrej Karpathy Guidelines (กฎเหล็ก AI)

กฎการตรวจสอบความจริงเชิงประจักษ์ มุ่งเน้นการลดอาการเดาสุ่ม (Hallucination) ของโมเดลภาษา:

### 1. `andrej-karpathy-guidelines` (4 กฎเหล็กควบคุม AI)
- **กลไกการทำงาน:** `Always-On Guardrail (รันเบื้องหลังตลอดเวลา)`
- **ตรรกะการรัน:** ฝังอยู่ใน Steering File หลักของทุกแพลตฟอร์ม บังคับให้เอเจนท์ต้อง:
  1. รันตรวจสอบจริงเสมอห้ามคิดไปเอง
  2. อ้างอิงสเปกคู่มือจริงห้ามเดา
  3. เขียนโค้ดอย่างค่อยเป็นค่อยไปจำกัดสมาธิ
  4. ปฏิเสธงานคลุมเครือเพื่อตั้งคำถามมนุษย์ทันที
- **คำสั่งเรียกใช้:** ตรวจจับพฤติกรรมอัตโนมัติเบื้องหลังตลอดเวลาทุกครั้งที่เอเจนท์ขยับทำงาน

## ⛓️ 3. Loop Engineering (วิศวกรรมควบคุมลูป)

กลุ่มทักษะเพื่อคุมวินัยทรัพยากร ป้องกันการรันวนเป็นลูปอนันต์และประหยัดงบประมาณโทเคน:

### 1. `loop-budget` (งบประมาณการรันลูป)
- **กลไกการทำงาน:** `Always-On Guardrail (รันเบื้องหลังตลอดเวลา)`
- **ตรรกะการรัน:** แทร็กและระบุเพดานโควตา Token สูงสุด และจำนวนตาโต้ตอบสูงสุดในแต่ละ Session หากเกิดเหตุ AI วิ่งเลยเกณฑ์จะปิดกระบวนการทำงานทันที
- **คำสั่งเรียกใช้:** คอยจับพฤติกรรมเบื้องหลังอัตโนมัติ หรือเรียกเช็คสถานะด้วย `/skill loop-budget`

### 2. `loop-constraints` (ข้อจำกัดควบคุมลูป)
- **กลไกการทำงาน:** `Always-On Guardrail (รันเบื้องหลังตลอดเวลา)`
- **ตรรกะการรัน:** บีบขอบเขตเวลาและจำกัดจำนวนไฟล์ที่ AI สามารถรื้อแก้ในหนึ่งสเต็ป เพื่อล็อกเป้าหมายไม่ให้ AI เตลิดเตลยนอกกรอบ
- **คำสั่งเรียกใช้:** บังคับใช้เบื้องหลังตลอดเวลา

### 3. `loop-triage` (การประเมินลูปวน)
- **กลไกการทำงาน:** `Workflow-Activated (ทำงานเมื่อเข้าเฟสที่กำหนด)`
- **ตรรกะการรัน:** ทำงานในเฟสดีบั๊ก หากแก้ไขโค้ดแล้วล้มเหลวเกิน 2 ครั้ง ระบบจะวิเคราะห์เพื่อเปลี่ยนวิธีการเดินหน้าและจัดหมวดข้อผิดพลาดใหม่
- **คำสั่งเรียกใช้:** เรียกใช้อัตโนมัติเมื่อเกิดข้อผิดพลาดในการรันคอมไพล์ซ้ำซ้อน

### 4. `loop-verifier` (ตัวพิสูจน์ลูปวนแก้บั๊ก)
- **กลไกการทำงาน:** `Always-On Guardrail (รันเบื้องหลังตลอดเวลา)`
- **ตรรกะการรัน:** คอยสแกนคำสั่งรันแก้ หากพบพฤติกรรมว่า "AI พยายามเขียนสลับลูปแก้บั๊กจุดเดิมด้วยโค้ดเดิมๆ ซ้ำเกิน 3 ครั้ง" จะสั่งปิดหน้าต่างแชททันทีแล้วส่งเสียงเรียกมนุษย์ให้ช่วยแก้ทาง
- **คำสั่งเรียกใช้:** รันอยู่เบื้องหลังเพื่อป้องกันกระเป๋าเงินฉีกจากการวนส่ง API โดยไม่รู้ตัว

### 5. `minimal-fix` (การแก้จุดบั๊กที่เล็กที่สุด)
- **กลไกการทำงาน:** `Workflow-Activated (ทำงานเมื่อเข้าเฟสที่กำหนด)`
- **ตรรกะการรัน:** สั่งบังคับตรรกะ AI ให้เลือกวิธีซ่อมแซมโค้ดที่รัดกุมและแตะต้องไฟล์น้อยที่สุดเพื่อควบคุมผลข้างเคียง (Side Effects)
- **คำสั่งเรียกใช้:** อัญเชิญอัตโนมัติเมื่อเอเจนท์ Specialist ทำการดีบั๊กแก้บั๊กทั่วไป

## ⚡ 4. Superpowers (ทักษะกระบวนการพัฒนาระดับซูเปอร์พาวเวอร์)

ระบบอัตโนมัติในการช่วยวางแผนพัฒนา จัดระเบียบการจัดส่ง และวิเคราะห์สถาปัตยกรรม:

### 1. `brainstorming` (การระดมสมอง)
- **กลไกการทำงาน:** `Slash Command (เรียกใช้งานตรงๆ)`
- **ตรรกะการรัน:** เริ่มกระบวนการคิด แตกฟังก์ชันสเปก และจับคู่ระดมความคิดเห็นร่วมกับผู้ใช้เชิงสถาปัตยกรรม
- **คำสั่งเรียกใช้:** `/skill brainstorming`

### 2. `dispatching-parallel-agents` (การสั่งรันเอเจนท์ขนาน)
- **กลไกการทำงาน:** `Workflow-Activated (ทำงานเมื่อเข้าเฟสที่กำหนด)`
- **ตรรกะการรัน:** ทำหน้าที่เป็นตัวกระจายงานย่อยที่เป็นอิสระออกจากกัน ส่งลงไปที่ Specialist Sub-agents เพื่อกวดขันความเร็วทำงาน
- **คำสั่งเรียกใช้:** เรียกใช้งานโดยเอเจนท์หลัก `aidlc-lead` หรือสั่งตรงๆ ด้วย `/skill dispatching-parallel-agents`

### 3. `executing-plans` (การลงมือตามแผนงาน)
- **กลไกการทำงาน:** `Workflow-Activated (ทำงานเมื่อเข้าเฟสที่กำหนด)`
- **ตรรกะการรัน:** คุมขั้นตอนปฏิบัติโค้ดตามแผนงานที่ได้รับการอนุมัติทีละสเต็ป ล็อกเป้าหมายไม่ให้ทำงานข้ามคิว
- **คำสั่งเรียกใช้:** สั่งใช้งานเมื่อเริ่ม Phase 5 หรือพิมพ์ `/skill executing-plans`

### 4. `finishing-a-development-branch` (การปิดสายงานกิ่งพัฒนา)
- **กลไกการทำงาน:** `Slash Command (เรียกใช้งานตรงๆ)`
- **ตรรกะการรัน:** ไล่รันตรวจสอบคุณภาพบิวด์ คอมไพล์ ไทป์ และเทสรวมให้ผ่าน 100% ก่อนทำประวัติจัดเตรียมรวมสาขากิ่งงาน Git
- **คำสั่งเรียกใช้:** `/skill finishing-a-development-branch`

### 5. `receiving-code-review` (การรับฟังการรีวิวโค้ด)
- **กลไกการทำงาน:** `Workflow-Activated (ทำงานเมื่อเข้าเฟสที่กำหนด)`
- **ตรรกะการรัน:** นำรายละเอียดฟีดแบกของระบบตรวจสอบมาวิเคราะห์ แตกขั้นตอนซ่อมแซม และลงมือแก้ไขอย่างเป็นระบบ
- **คำสั่งเรียกใช้:** รันเมื่อผลตรวจ Gate ถูกตีกลับ หรือเรียกด้วย `/skill receiving-code-review`

### 6. `requesting-code-review` (การส่งรีวิวโค้ด)
- **กลไกการทำงาน:** `Workflow-Activated (ทำงานเมื่อเข้าเฟสที่กำหนด)`
- **ตรรกะการรัน:** รันกระบวนการตรวจวิเคราะห์โค้ดตามสเปกและหลักการ Clean Code ก่อนยื่นส่งให้มนุษย์รีวิว
- **คำสั่งเรียกใช้:** เรียกใช้งานอัตโนมัติในขั้นตอน Gate Review หรือเรียกด้วย `/skill requesting-code-review`

### 7. `subagent-driven-development` (การพัฒนาด้วยซับเอเจนท์)
- **กลไกการทำงาน:** `Workflow-Activated (ทำงานเมื่อเข้าเฟสที่กำหนด)`
- **ตรรกะการรัน:** สั่งงานให้ Specialist Sub-agents ทำงานเขียนโค้ดหรือชุดทดสอบเฉพาะจุดเพื่อคงสมาธิ
- **คำสั่งเรียกใช้:** เรียกโดย Orchestrator ระหว่าง Phase 5

### 8. `systematic-debugging` (การดีบั๊กอย่างเป็นระบบ)
- **กลไกการทำงาน:** `Workflow-Activated / Slash Command`
- **ตรรกะการรัน:** รันขั้นตอนตรวจวิเคราะห์บั๊ก: ตั้งทฤษฎี $\rightarrow$ คาดการณ์ $\rightarrow$ รันเช็คความจริง $\rightarrow$ ยืนยันพยานหลักฐานหลังซ่อมแซม
- **คำสั่งเรียกใช้:** `/skill systematic-debugging [คำอธิบายอาการ]`

### 9. `test-driven-development` (เขียนเทสนำหน้าโค้ด)
- **กลไกการทำงาน:** `Workflow-Activated (ทำงานเมื่อเข้าเฟสที่กำหนด)`
- **ตรรกะการรัน:** วางโครงเขียนและรันชุดทดสอบ Unit Test ให้เรียบร้อยก่อนเขียนโค้ดตัวแอปจริง
- **คำสั่งเรียกใช้:** เรียกอัตโนมัติใน Phase 5 เมื่อเริ่มสร้างโมดูล หรือสั่งตรงๆ ด้วย `/skill test-driven-development`

### 10. `using-git-worktrees` (การจัดการพื้นที่ด้วย Git Worktree)
- **กลไกการทำงาน:** `Slash Command (เรียกใช้งานตรงๆ)`
- **ตรรกะการรัน:** สั่งดึงสาขากิ่งงานขึ้นมาทำงานขนานในโฟลเดอร์แยกเฉพาะกิจเพื่อความปลอดภัยต่อไฟล์งานหลัก
- **คำสั่งเรียกใช้:** `/skill using-git-worktrees [ชื่อกิ่งงาน]`

### 11. `using-superpowers` (การเปิดใช้ระบบซูเปอร์พาวเวอร์)
- **กลไกการทำงาน:** `Always-On Guardrail (รันเบื้องหลังตลอดเวลา)`
- **ตรรกะการรัน:** เชื่อมโยงและจัดสรรการทำงานร่วมกับเวิร์กสเปซและเครื่องมือภายนอกทั้งหมด
